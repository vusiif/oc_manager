# OC Manager — Relation Studio 2.0 关系图重构实施计划

> 文档性质：专项技术与产品实施方案（不是 AGENTS.md）。  
> 建议目标版本：v1.9.0，最终版本号由维护者决定。  
> 审查基线：用户提供的 `oc_manager-main.zip`，Commit `9edf7c5a004010e2a006f69242dce37eea19cc96`；`pubspec.yaml` 为 `1.8.0+5`，数据库 Schema v15。README 声称 140 项测试通过，本次未运行 Flutter 客户端或测试。  
> 核心决策：**重写关系图编辑器，而非继续修补旧 Widget；保留现有业务数据、DAO 和已验证的算法。**

## 0. 执行摘要

目前 OC Manager 已具备多画布、关系创建、家谱、过滤、自动布局、撤销重做、最短路径、视口裁剪、LOD、小地图和导出等功能。重构的目的不是重新实现这些功能清单，而是让这些能力建立在统一、可靠的编辑器架构上。

新版关系图命名暂定 Relation Studio（关系工作台）。目标体验是一个面向原创角色创作的可视化编辑器：选中、拖动、框选、连线、整理、编辑属性和导出都可以自然完成。保留 Windows 和 Android 支持，以及本地优先、无需联网的产品原则。

**重构范围：** 编辑器状态、手势、视口坐标、场景几何、渲染、命令执行、工具栏与属性面板。

**不在重构范围：** 整个应用架构、人物档案系统、世界观百科、已有关系业务规则、数据库整体换代。第一期不做云同步、AI、插件系统，也不把关系图改成通用无限白板产品。

**交付策略：** 新模块并行开发 → 核心交互验证 → 现有功能对等 → 新入口切换 → 删除旧编辑器。禁止长期维护两套可写编辑器或两份业务数据。

## 1. 现有实现审查

### 1.1 源码证据与重构理由

以下结论对应上传 ZIP 中的实际文件；交互是否在所有设备上复现，仍需运行验证。

| 源码路径（相对于仓库根目录） | 已观察到的实现 | 风险或改造方向 |
|---|---|---|
| `lib/features/relation/relation_graph_page.dart` | 页面持有 `_positions`、`_loadedFromDbCharacters`、`_connectingFromId`、`_selectedRelationId`、`_historyManager`、视口与过滤等状态 | 页面承担过多职责；建立统一编辑器文档、会话和瞬态交互状态 |
| `lib/features/relation/widgets/relation_canvas_view.dart` | `InteractiveViewer` 的平移与缩放受 `_isNodeInteracting` 控制；内容容器至少 3000×3000，并依赖节点最大正坐标扩展 | 多层手势协调难维护；无限平移不等于无限可编辑空间 |
| `lib/features/relation/relation_graph_node.dart` | 节点内部 `_pos`；三种 LOD 分支重复拖动逻辑；坐标使用 `max(40.0, ...)`；完整模式中有鼠标悬停相关的连接手柄 | 坐标来源不统一；负坐标受限；LOD 改变时交互能力可能不同；取消拖动当前会调用结束逻辑 |
| `lib/features/relation/widgets/relation_connection_helper.dart` | `hitTestRelation()` 对 `calculateRelationLabelCenters()` 的结果做距离判定；`findConnectTarget()` 按中心距离遍历 | 不能普遍沿线选中关系；多关系和家谱标签容易产生选择歧义；连接目标应按实际边界、层级与距离判定 |
| `lib/features/relation/relation_graph_painters.dart`、`painters/relation_label_helper.dart`、`graph_geometry.dart`、`graph_svg_exporter.dart` | 绘制、标签位置、几何和导出分别处理相关计算 | 需要统一场景几何，避免显示、命中、导出各有一套规则 |
| `lib/features/relation/widgets/relation_graph_commands.dart` | `dropCharacter()`、`removeCharacter()`、`recordNodeMove()` 发起持久化后不等待即记录历史 | 写入失败或快速切换画布时可能出现状态不一致；改为可等待的事务命令 |
| `lib/features/relation/graph_history_manager.dart` | 现有命令模式；`undo()`/`redo()` 在执行异步操作前 `removeLast()` | 命令失败可能导致历史项丢失；应在成功后移动栈顶，失败时保留历史和一致状态 |
| `lib/features/relation/widgets/relation_canvas_state_helper.dart` | 保存矩阵平移、缩放、过滤配置；节点坐标只在未加载时同步 | 需要明确加载代次、外部数据变化、会话边界和持久化生命周期 |
| `lib/data/database/daos/canvas_dao.dart` | 默认画布、复制、删除、视口、过滤、坐标保存等能力已存在；读取坐标按人物保留最新记录 | 优先复用；补充事务、归属校验及并发保护，而不是重写整套 DAO |

截图中的具体问题：顶部无文字图标过密；左栏人物资源状态不清晰；同一对人物的多个标签重叠；家谱折线靠近或穿过名称和节点；默认性别几何形状不利于辨认 OC；小地图占用固定空间。截图不能单独证明所有手势或持久化问题，运行测试仍是必要的。

### 1.2 保留、替换与适配矩阵

| 模块 | 处理方式 |
|---|---|

| `test/graph_*`、`test/relation_*` 等现有测试 | 保留业务契约；对旧 Widget 私有实现的测试改写为等价行为测试，不删除覆盖以换取通过 |

## 2. 产品范围与验收目标

### 2.1 发布门槛（P0）

- 选择、拖动、平移、缩放、连线、取消操作互不冲突。
- 同一对人物的多条关系可以分别阅读和选中；家谱分组能正确表示。
- 支持负世界坐标、鼠标锚点缩放、触屏双指缩放、适应全部节点。
- 新版打开现有数据不丢失人物、画布、位置、视口、过滤和关系分组。
- 现有主要能力全部对等：多画布、关系创建编辑删除、家谱、自动布局、历史、过滤、路径、小地图、PNG/SVG 导出。
- 数据库写入失败时不会出现虚假的“保存成功”或丢失历史记录。
- Windows 与 Android 分别经过实际操作验收。

### 2.2 体验增强（P1，按里程碑拆分）

头像卡片、可折叠资源栏、属性检查器、搜索定位、多选与批量拖动、对齐吸附、简洁节点样式、连线路由改善、便捷关系类型菜单。优先实现前述交互和视觉；新增需要 Schema 的功能留给单独评审。

### 2.3 后续能力（P2，不阻塞重构）

画布分组与折叠、便签与参考图、手动弯折点、画布专属样式、动态关系时间轴、跨实体知识图、演示模式。必须在新编辑器稳定后逐项实施。

## 3. 新版 UI 与交互规范

### 3.1 Windows 布局

```text
┌────────────────────────────────────────────────────────────────┐
│ 返回  关系工作台  [主画布 ▾]  +  │ 撤销 重做 │ 布局 筛选 导出 ⋯ │
├───────────────┬──────────────────────────┬─────────────────────┤
│ 人物资源库  ‹ │  [选择] [手型] [连线] … │ 属性检查器       › │
│ 搜索人物      │                          │ 选中人物/关系/分组 │
│ 全部 / 未放置 │       ┌─────────┐        │                     │
│ ○ 长亭  定位  │       │ 头像 长亭│        │ 类型 / 方向 / 备注 │
│ ○ 陈胜王  +   │       └────┬────┘        │                     │
│ ○ 奶龙   +    │          朋友            │ 节点显示 / 关系列表 │
│               │       ┌────┴────┐        │                     │
│               │       │头像 陈胜王│       │ 打开完整人物档案   │
│               │  − 100% + 适应  [小地图] │                     │
└───────────────┴──────────────────────────┴─────────────────────┘
```

- 顶部只放全局操作：画布切换、撤销重做、布局、过滤、导出；低频功能收入更多菜单。图标有 Tooltip、快捷键提示和无障碍名称。
- 左栏建议初始宽 220–260 逻辑像素，可收起。人物列表有头像、姓名、放置状态、搜索、拖放和定位；已放置者仍然可选择，不降低到不可读的灰色。
- 中央画布是主角。悬浮工具栏仅放当前操作模式（选择、平移、连线）；分组、便签工具在对应阶段开放。
- 右栏建议初始宽 280–320 逻辑像素，可收起；无选中时展示画布属性，有选中时显示人物、关系或多选属性。正常编辑不强制弹窗；危险修改、跨画布影响等仍需确认。
- 小地图可开关，缩放控件显示当前比例与适应全部/选中节点。窄窗自动折叠面板，保证可操作区域。
- 深浅主题复用现有设计系统；背景采用低对比网格或点阵。关系线色彩不压过节点。禁止为每个功能随意新建一套颜色和圆角。

### 3.2 Android 布局

保留顶部简化画布切换及更多菜单；人物资源库改为抽屉，属性检查器改为可收起底部面板。平移/选择/连线模式采用可见控件。重要操作不依赖鼠标悬停、右键或物理键盘；所有触控目标建议至少 48dp。软键盘打开时画布与面板保持合理布局，返回操作优先退出当前交互、再关闭面板、最后离开页面。

### 3.3 手势与键盘契约

| 操作 | Windows | Android |
|---|---|---|
| 选择节点/边 | 单击 | 单击 |
| 打开人物档案 | 双击或明确按钮 | 详情按钮 |
| 移动节点 | 选择模式下按住节点拖动 | 选择模式下单指拖动节点 |
| 移动画布 | 中键、空格+左键、手型模式拖动 | 单指拖动空白；手型模式可从节点上开始平移 |
| 框选 | 选择模式拖动空白区域 | 显式多选工具拖动空白 |
| 多选 | Shift+单击，Shift 框选追加 | 多选模式点选 |
| 缩放 | 滚轮以指针为锚点 | 双指以中心为锚点 |
| 创建关系 | 拖动节点锚点，或连线模式点选两端 | 连线模式点选两端；可选锚点拖动 |
| 取消 | Esc | 取消按钮或返回 |
| 菜单 | 右键 | 长按（与拖动互斥） |
| 删除/移出 | Delete（根据选择类型显示明确语义） | 属性面板操作 |
| 撤销/重做 | Ctrl+Z / Ctrl+Shift+Z（可兼容 Ctrl+Y） | 工具栏按钮 |
| 搜索、适应全部 | Ctrl+F / F（仅画布焦点） | 明确按钮 |

文本输入、下拉菜单、对话框获得焦点时禁止画布快捷键误触。鼠标移动超过阈值才判定为拖动；阈值建议初始 4–6 逻辑像素，触屏独立调校。单击和双击不得导致重复打开/保存操作。

### 3.4 状态机

建议使用显式会话状态，而不是在各 Widget 中维护互相依赖的布尔值：

| 状态 | 进入条件 | 正常结束 | 取消/异常 |
|---|---|---|---|
| idle / pressed | 指针按下并完成命中测试 | 点击选择或进入其他状态 | 清理指针会话 |
| draggingNodes | 节点命中且超过拖动阈值 | 提交一条移动命令 | 恢复拖动前坐标 |
| panning | 手型/中键/空格/触屏空白拖动 | 保存视口（防抖） | 终止会话，不写业务数据 |
| zooming | 滚轮/双指缩放 | 更新视口 | 清理指针；不误提交节点拖动 |
| boxSelecting | 选择模式空白拖动 | 更新选中集合 | 恢复原选择 |
| connecting | 锚点拖动或连线模式选择源 | 命中目标，等待关系类型确认 | 清除临时线，不创建关系 |
| reconnecting（P1） | 现有边端点拖动 | 确认修改关系 | 恢复原关系 |
| awaitingRelationType | 连接成功 | 选择类型并提交命令 | 不留下空关系 |

交互会话由一个控制器管理；渲染组件只读取状态。PointerCancel、焦点丢失、窗口切换、设备旋转、切换世界观/画布时必须有确定的退出行为。第二根手指加入未提交的节点拖动时，建议取消该拖动再进入缩放，避免意外保存。

## 4. 技术架构设计

### 4.1 目录建议

```text
lib/features/relation_editor/
  domain/           # GraphDocument、Node、Edge、Selection、Viewport
  application/      # 会话控制器、命令调度、Repository 适配器
  interaction/      # 指针状态机、快捷键、工具模式、手势意图
  geometry/         # 场景布局、节点边界、路由、标签布局、命中检测
  rendering/        # 背景、边、节点、选中态、临时连接线
  presentation/     # 页面、画布、人物库、工具栏、检查器、小地图
  exporters/        # 场景快照到 PNG / SVG 的转换
```

不必机械地创建所有文件。先实现最小模块，只有职责明确且出现真实复用需求时再拆分。继续使用 Flutter、Riverpod、Drift 和 go_router，不引入新的全局状态管理框架。

### 4.2 状态所有权

| 数据 | 唯一所有者 | 生命周期 |
|---|---|---|
| 真实人物/关系记录 | 数据库与 Repository | 世界观级，共享给所有画布 |
| 画布放置、布局、过滤、视口 | GraphDocument / 持久化适配器 | 当前 `(worldId, canvasId)` |
| 选择、悬停、工具模式 | EditorSession | 打开画布的会话 |
| 临时拖动位置、框选矩形、连线预览 | InteractionSession | 单次手势；未提交不写 DB |
| 路径、边界、标签位置 | SceneGeometry | 由文档与视图派生，可缓存，不作为第二份业务数据 |
| Undo/Redo | CommandEngine | 当前会话；切换画布时清理（第一版） |

GraphDocument 不复制真实人物表，不让 UI 直接修改 DAO。Riverpod 可按 `(worldId, canvasId)` 管理会话并细粒度订阅。高频指针更新通过局部监听或 Listenable 驱动，避免全页面重建。外部人物删除/修改通过数据订阅同步；若与当前拖动或命令冲突，取消相关预览并重新载入，不静默覆盖。

### 4.3 坐标与视口契约

统一使用画布视口局部逻辑像素（screenLocal）与世界坐标（world）。节点存储以**中心点**为锚；旧节点使用中心点定位，迁移时保持原坐标语义。禁止把全局屏幕坐标直接作为局部坐标。

```text
screenLocal = world × scale + translation
world = (screenLocal - translation) / scale
worldDelta = screenDelta / scale
newTranslation = anchorScreen - anchorWorld × newScale
```

- 进入画布前使用 RenderBox.globalToLocal 等转换全局指针坐标。
- 使用统一 viewport transform；若采用 TransformationController，明确其矩阵与上述契约的一致性，不再同时维护另一个偏移。
- 支持负坐标；不通过不断扩大巨型 Stack 来模拟无限画布。推荐固定大小 viewport，按变换绘制世界内容或定位可见节点。是否保留 InteractiveViewer 由原型验证决定；如果难以控制手势与负坐标，改用统一指针控制器和自定义视口。
- 缩放初始建议范围 0.1–4.0，具体根据 LOD/可读性调校。所有输入必须有限且尺度为正，拒绝 NaN/Infinity。
- Fit to all 根据可见内容边界、面板后的真实 viewport 尺寸和边距计算；空画布回到默认视口，不除以零。
- 小地图使用相同世界边界与变换，支持负坐标、点击导航和视口矩形拖动。

### 4.4 统一场景几何与边路由

建立一个纯逻辑 SceneGeometryBuilder，输入节点位置、节点显示边界、关系记录、过滤与渲染配置，输出至少包含：

```text
NodeGeometry: stableKey, bounds, outline, ports, zOrder
EdgeGeometry: stableKey, relationIds, segments/path, bounds,
              sourcePort, targetPort, labelBounds, arrowheads
GroupGeometry: groupKey, trunkSegments, branchSegments, memberRelationIds
SceneGeometry: nodes, edges, groups, contentBounds, revision
```

几何对象示意，不是强制 Dart API。画布绘制、命中检测、小地图、PNG/SVG 导出从同一个几何生成器取得结果；导出可使用独立的全量显示配置，但不能复制一套不一致的布线路径。

**普通关系路由：** 根据节点边界计算端点而非中心；同一人物对的关系按稳定 ID 排序分配不同 lane；反向边使用规范化端点顺序避免重叠；支持曲线和折线，箭头与方向来自业务关系数据。标签应沿不同 lane 错开，基于文字实际边界避让节点和已放置标签。拥挤时允许次要标签隐藏，选中/悬停显示完整文字，并通过检查器保留所有关系的访问入口。第一期不承诺全局最优无交叉布局。

**家谱路由：** 保留 `relationGroupId` 与现有亲属语义，独立计算总干线、连接点、各分支。选择公共干线应选择整个家谱组，选择独立分支则对应明确关系；无法唯一判定时显示关系候选。不得把家谱组退化成若干语义不明的普通边。基础家谱使用正交路由，优先避开人物卡片与名称区域。

**命中顺序：** 明确锚点/端点 > 节点 > 标签 > 可见关系线/家谱分支 > 背景。边命中使用到实际曲线或折线的距离，曲线可按误差容限细分为线段；命中容差按屏幕逻辑像素定义（初始鼠标 6–8px，触控更宽），换算到世界坐标。候选以距离和 z-order 稳定排序；重叠时支持列表选择，不以遍历顺序随意命中。过滤掉的边不接受点击。

### 4.5 节点视觉与渲染

- 默认采用头像 + 姓名的圆角卡片；无头像时显示 initials/首字占位。标准卡片建议宽 140–180、高 56–72（世界单位），需根据字号和实际文本调整。
- 提供紧凑模式、标准模式、立绘模式；原圆形/方形/菱形保留为家谱视图。第一期无需新增持久化样式字段，可用全局视图模式验证。
- LOD 只控制信息密度：远景小点/姓名，中景头像姓名，近景补充字段。交互仍由统一命中与指针控制器管理，不重复实现三套拖动逻辑。卡片边界变化必须通知几何引擎。
- 选中态用清晰边框和锚点；非相关节点可降低透明度；不可仅用颜色传达重要信息。
- 推荐混合渲染：CustomPainter 负责网格、边、临时预览；可见节点使用轻量 Widget 或 Painter（由原型性能和无障碍验证决定）。使用 RepaintBoundary 与分层监听，单节点拖动不重建整个资源栏和检查器。
- 视口裁剪基于实际节点/边 bounds 与缓冲区，不能只因两端不在屏幕内就隐藏横穿视口的边。拖动时只更新受影响的邻接边，复杂避障可在手势结束后重新计算。

### 4.6 命令系统与保存

推荐事务后确认的模型：拖动期间使用瞬态预览，结束时提交一条命令；命令写入成功后发布已提交状态、进入历史栈。失败时恢复操作前状态，给出可重试错误提示。若采用乐观更新，必须有显式回滚快照与并发顺序控制。

```text
用户意图 → 校验命令及会话归属 → 临时预览（可选）
        → 串行事务提交 → 成功：更新状态、记录历史、刷新订阅
                    ↘ 失败：回滚预览、保留原历史、提示错误
```

命令至少覆盖 PlaceNode、RemoveNodeFromCanvas、MoveNodes、CreateRelation、UpdateRelation、DeleteRelation、CreateFamilyGroup、ApplyAutoLayout。命令捕获固定的 worldId/canvasId 和稳定 ID；批量移动/家谱创建在同一事务内执行；Redo 必须正确处理原始 ID 与关联。撤销/重做成功后才移动历史栈，失败保留栈顶。新命令成功才清空 redo。一次拖动只记一条；视口缩放不记入业务历史。

持久化队列按画布会话串行；快速切换时等待已开始的提交或提供明确失败提示。防抖保存视口/过滤，保存时捕获不可变的目标 ID 与变换，不读取后来切换的画布。页面销毁、应用后台和退出前明确处理待保存状态；不让旧会话回调污染新画布。不要依靠 `dispose()` 中不可等待的异步写入保证数据安全。

## 5. 数据兼容、迁移与发布保护

### 5.1 第一版尽量保持 Schema v15

当前数据结构已经足够支撑基础重构：

- `GraphCanvases`（`lib/data/database/tables/canvases.dart`）：`id`、`worldId`、名称、默认标志、`viewportX/Y`、`zoomScale`、`filterConfig` 等。
- `GraphLayouts`（`lib/data/database/tables/trash.dart`）：`worldId`、`characterId`、`x/y`、可空 `canvasId`。
- `Relations`（`lib/data/database/tables/relations.dart`）：`fromCharacterId`、`toCharacterId`、`relationType`、`isBidirectional`、`note`、`relationGroupId`。

新版通过 Repository 读取这些数据；布局沿用中心坐标，视口沿用旧矩阵平移和缩放含义。先以兼容适配器处理旧 `canvasId == null` 的布局和重复历史记录（现有 DAO 已有默认画布绑定和按最新记录读取的逻辑），不无条件批量改写数据。保持原人物、关系和画布 ID。

### 5.2 视图操作与真实数据严格分离

| 操作 | 允许影响 |
|---|---|
| 从画布移出人物 | 当前画布布局，不删除人物、关系或其他画布节点 |
| 删除人物档案 | 走原人物删除/回收站业务入口，明确确认 |
| 隐藏/过滤关系 | 只改变当前画布显示 |
| 删除真实关系 | 修改世界观关系数据，影响全部相关画布，必须清晰提示 |
| 修改显示颜色/尺寸 | 视图设置，不改变关系类型 |
| 复制/删除画布 | 布局及其视图设置，不复制或删除真实关系 |

关系编辑遵循现有 `relation_provider.dart` 和 DAO 的校验规则；不得绕开世界观隔离、重复关系验证或锁定状态的约束。

### 5.3 如果后续确实需要 Schema v16+

仅为已经确认的功能增加字段或表，例如画布专属节点样式、分组、便签、边折点。不把这些功能一并塞进核心重构。提出设计：ID、归属、唯一约束、索引、删除、恢复、复制、导入导出、旧版读取。注意现有 `GraphLayouts.canvasId` 可空且没有组合唯一约束；若要新增唯一约束，应先检查重复与空值，按确定策略迁移，避免任意删除历史数据。

升级前创建一致性备份；用实际旧版本数据库 fixture 验证迁移、回收站、`.ocpkg`、完整备份和数据往返。应用降级不能假设可读取新 Schema；若已迁移，回退应使用升级前备份。第一期不改变格式时，也应检查新版保存的负坐标能否在旧编辑器正常展示，不能把旧页面当作完全可靠的回滚机制。

### 7.2 手工体验验收脚本

1. 打开含六个人物、普通边与家谱边的旧世界观；检查名称、方向、分组、位置。
2. 鼠标滚轮放大到 200%，拖动任一人物，再缩回 50%；检查位置无跳变，关系端点跟随。
3. 把人物拖到负坐标；关闭重开、切换画布、适应全部后仍存在且可定位。
4. 框选三个节点一起移动；撤销和重做各一次；检查数据库和视觉位置一致。
5. 给同一对人物建立朋友、恋人、敌对等多条关系，分别点击曲线和标签；选择正确的关系。
6. 创建家谱，点击干线和分支分别编辑；删除/撤销后成员关系正确。
7. 开始拖动或连接后按 Esc；确认无意外写入。模拟写入失败后历史与图保持一致。
8. 在 Android 实机双指缩放、长按、切换连线模式、打开底部面板、返回、旋转屏幕；确认没有误拖动或丢失操作。
9. 创建第二张画布并复制布局，移出一个人物；确认第一张画布与人物档案不受影响。
10. 导出 PNG/SVG，与同一筛选条件下画布核对箭头、关系标签、图片与家谱结构；保存重开后再次检查。

| 1000 节点 / 3000 边 | 压力测试；另设多重边与家谱密集图 |

在固定的 Windows 设备与至少一台 Android 实机上记录 CPU/GPU、分辨率、刷新率、构建模式、测试数据和运行时长。使用 profile 模式及 Flutter DevTools，不以 debug 模式数据作为发布性能结论。

建议目标：100 节点常规交互争取接近 60Hz（UI/raster 帧耗时以 16.7ms 作为参考）；500 节点通过裁剪和 LOD 保持可编辑，争取 p95 帧耗时不超过 33ms；1000 节点允许降级显示，但不崩溃、不出现长时间无响应。实际门槛需按基线硬件确认，避免声称未经测量的 FPS。记录首次加载、帧耗时分位数、内存、连续切换画布后的资源增长及拖动期间数据库写入次数。重复测试至少三次；不要仅展示最佳结果。

导出应限制合理像素预算，超大图给出降低分辨率或选择 SVG 的建议；不能直接申请无限大小位图。检查图片缓存、字体布局和导出临时资源的释放。

## 8. 风险与防止二次技术债

| 风险 | 防护措施 |
|---|---|
| 新版又形成巨型页面 | 页面只组合 UI；交互/几何/命令可独立测试；按职责而非文件数量评审 |
| 重写时功能退化 | Phase 0 固化旧功能矩阵；Phase 4 对等；正式切换前验收 |
| 迁移破坏数据 | 第一期保持 v15；旧数据 fixture 与备份；Schema 变更单独评审 |
| 旧版与新版同时写入 | 开发阶段使用隔离数据或单会话；正式版只有一个写入口 |
| 关系边语义错误 | 业务关系 ID 与几何对象分离；家谱单独路由；多重边和组选择测试 |
| Android 仍不易用 | Phase 1 就测试真实触屏，不能等 UI 做完后才适配 |
| 性能优化变成过度设计 | 先测量，按热点优化；空间索引、复杂避障、全量 Painter 化仅在有证据时采用 |
| 导出和屏幕再次不一致 | 几何引擎统一；导出使用明确的场景快照和显示选项 |
| Scope creep | RS-060+ 不阻塞 P0；不提前实现通用白板、动态关系、云同步 |
| 历史任务串写 | 命令队列捕获固定会话；失败保留历史；切换时处理待提交任务 |

## 9. 实施约束与完成定义

- 先完成一个里程碑，不并行修改大量无关模块。每个任务先核对当前实现是否已满足需求。
- 禁止通过无休止增加 Helper、手势布尔量、重复状态 Map 来模拟解耦；每个新状态必须有明确所有者。
- 保留原数据库和业务能力；不为重构删除现有数据，也不使用重置数据库的方法让测试通过。
- 不引入未经评审的大型画布依赖。若评估现成 Flutter 图编辑库，应先验证 Windows/Android、许可证、可维护性、负坐标、家谱自定义路由、命中、导出与事务能力。
- 每阶段提交说明：实际完成项、关键文件、未完成项、测试命令与结果、数据影响、下一阶段依赖。已有 TODO 的 GRAPH-001–005 保持完成状态，新增 RS 任务表达重构工作。
- 不擅自发布版本、推送、删除用户未提交代码；清理旧模块只在功能对等验证和维护者确认后进行。
